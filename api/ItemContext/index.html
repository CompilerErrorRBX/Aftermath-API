ItemContext

Item context actions -- Equip, Drop, Consume, Scrap, Use With.

Replaces Item/Context/BaseContext.luau and the :Extend() chain under it. A context is now a plain table of data plus function fields; there is no prototype, no class, and nothing injected at load.

WHAT CHANGES

  • One typed request instead of five positional arguments. The old handlers took (client, item_id, owned, context_item_id, metadata) on the server and (item_id, client, metadata) on the client -- THE ORDER IS INVERTED between realms, which is a live footgun in a codebase where most contexts implement both. There is one ContextRequest record now.

  • Handlers are grouped under Client and Server rather than spread across six similarly-named methods. Which realm a handler belongs to is a fact about the handler, so it belongs in the shape.

  • AppliesTo (was ContextFilter) takes a CONFIG, not an item instance. It answers a question about the item KIND -- "can a backpack ever be scrapped" -- and the answer is the same for every instance, so it should not need one. This is what lets the context list be computed once per item kind at registration instead of per item.

ItemConfig is a tagged union, so config.EquipType is only reachable on the arms that have it. Weapons always carry one; Ammo and Attachments never do.
