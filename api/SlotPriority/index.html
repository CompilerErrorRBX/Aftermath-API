SlotPriority

Which slot an item should go in.

This is the one thing InventoryController did that Inventory2 did not. Its scoring machinery looked elaborate -- FillPriority spanning -inf to +inf, GetItemScore, GetSpaceInSlot returning a score alongside the space, GetSlotSpaceForItem sorting on it -- but InventorySlot:GetItemScore returns a constant 1, so for an ordinary slot the whole thing collapses to: 

same item first, then empty, lower index wins.

Which is exactly what HolderService.TransferToGroup already does with its two passes. The part that does NOT collapse is FilteredInventorySlot: it overrides GetItemScore to return FillPriority.Filter (5000) when its filters match and FillPriority.None (-inf) when they do not. Since the score is ADDITIVE with the Empty/Similar modifier, a matching filtered slot outranks everything -- an ammo pouch fills before an existing ammo stack elsewhere in the bag.

That ordering is what this module preserves. The tiers are kept at their original values so the two implementations can be compared numerically.

Score holder as a destination for config.

A holder with an Accepts predicate is the Inventory2 spelling of FilteredInventorySlot: matching earns the Filter tier, failing excludes it. Returns None for any holder the item cannot go in at all.
