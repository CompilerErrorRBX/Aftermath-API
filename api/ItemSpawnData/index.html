ItemSpawnData

Loot tables: what a spawner rolls, before anything is created.

WHAT CHANGED

ItemSpawnDataService mixed three jobs -- parsing Folder trees into spawn data, rolling that data into a result, and constructing item objects from the result. The middle one is the interesting one and the only one with real logic in it, so it lives here on its own.

It is now pure. Every function takes its SpawnData and its Random and returns a plain ItemSet tree; nothing is looked up, nothing yields, nothing is constructed. The original opened every public method with wait_service_ready(), which yielded until a Folder scan had finished -- so a loot roll could not be evaluated at all outside a booted place.

ItemSet was already the right intermediate. It names a class and a quantity and owns no identity, which is exactly an ItemStack minus the config lookup; ItemSpawnService does that half.

EMPTINESS

A spawner rolls empty more often on a busy server. That modifier was module state, recomputed from a player count and a Lighting attribute, and read implicitly by every call. It is a parameter here -- Options.ServerModifier -- which is what makes the threshold arithmetic testable at all.

AdjustedThreshold​

</>
ItemSpawnData:AdjustedThreshold(
threshold: number,
emptiness_modifier: number?,
server_modifier: number?
) → number

The emptiness threshold actually applied, after server fullness.

Exposed because it is the one piece of arithmetic here worth asserting directly, and because its direction is easy to get backwards.

With an explicit EmptinessModifier the threshold is simply scaled. Without one it runs the original's curve, where server_modifier is 1 on an EMPTY server and falls toward 0.5 as it fills. The curve turns that into a LOWER effective threshold, so a busy server spawns MORE -- and past a point it goes negative, meaning the emptiness check can never fire at all.

Preserved as it was. Whether that is the intended behaviour is a question for whoever owns the loot economy, but it is not a porting decision.

Roll​

) → {ItemSet}

Roll a spawner into a flat-ish list of ItemSets.

ItemReference spawners nest: they produce one parent whose Children hold everything the rest of the roll generated, which is how a crate spawns with things already inside it.

HasAnyItems​

ItemSpawnData:HasAnyItems(
spawn_data: SpawnData,
options: RollOptions?
) → boolean

Whether this spawner would produce anything, without rolling its contents.

Used to decide whether a container is worth spawning at all. Consumes the same random draws Roll would for its emptiness checks, so passing a fresh Random with the same seed to each gives consistent answers.
