ItemContextService

Registry and driver for item contexts.

Replaces Services/ItemContextService.service.luau.

WHAT CHANGES

  • Contexts are registered, not discovered by custom_require('*.itemcontext') on every call. GetValidContexts re-required the whole wildcard set and re-sorted it each time it was asked.

  • The per-kind context list is computed ONCE, at registration, and cached by ClassName. It only depends on the config, so recomputing it per item was pure waste.

  • The realm is a field, not RunService:IsClient() captured at module load. That is what makes both halves testable from one place, and it removes the branch from every call site.

  • The delay is scheduled through Schedule, which defaults to task.delay. Tests replace it; nothing else notices.

How long this context takes for this item.

The CONTEXT item's duration wins over the subject's -- using a slow tool on a fast item should take the tool's time. Carried over unchanged.

</>
ItemContextService:Cancel(request: ContextRequest) → boolean

Cancels whatever this player had in flight.

Returns whether anything was cancelled -- Activate uses that to make a second press of the same key abort rather than stack, which is what the old DectivateCurrentContextAction did.

name: string,
request: ContextRequest
) → boolean

Run a context.

Preaction runs immediately. If the context has a duration, Action is deferred and can be cancelled until it fires; otherwise Action runs inline.

Returns false when nothing was started -- either the context is unknown, or a press cancelled an action already in flight.
