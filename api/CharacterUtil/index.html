CharacterUtil

How to get a player's character in this game.

Player.Character IS NOT VALID HERE. The game runs the vendored CustomCharacter system, which owns character lifetime itself; the Roblox property is not the authority and may be nil or stale for a live player. PlayerList is, and its own comment says why:

Futureproof way to get a character from a player. Maybe the Character property on the Player will be removed one day!

Everywhere in src/ that needs a character already goes through PlayerList:GetCharacterFromPlayer -- the door actions, the landmine, InteractionService2. src2 does too, through here.

WHY A MODULE RATHER THAN THE CALL

Two reasons, both about not dragging a frozen system into places it does not belong.

PlayerList is stateful: it tracks players, runs a server runner, and registers itself in _G. A module that requires it at load pulls all of that into anything that requires the module -- including a headless test place with no players, where every lookup would return nil and every range check would silently fail closed.

So the require is LAZY and the lookup is one injectable seam. Production gets the real PlayerList without anyone wiring anything; a test overrides GetCharacter and never triggers the require at all.

CharacterUtil.GetCharacter(player: Player) → Model?

The seam. Defaults to PlayerList:GetCharacterFromPlayer.

Replace it to test anything that needs a character without standing up the CustomCharacter system: 

CharacterUtil.GetCharacter = function(player)
	return fake_characters[player]
end

RootPart​

</>
CharacterUtil:RootPart(player: Player) → BasePart?

The character's root part, or nil.

Read fresh every time on purpose. The old session record cached a PrimaryPart on client, which went stale across a respawn -- and with CustomCharacter a character can be replaced without the player rejoining, so caching is wrong more often here than it would be in an ordinary place.
